# 新手 5e 角色卡 PWA

日期：2026-09-10  
狀態：待你看過這份規格後才開始寫實作計畫

## 問題

5etools 對新手桌邊用手機太重。要一份中文、好點的角色卡，戰鬥時能改 HP／法術位，場次之間能升級，不要帳號、不要 DM 工具。

## 目標與非目標

**目標**

- 桌邊用手機：戰鬥一頁看完、大按鈕。
- 升級：一頁清單，勾完套用。
- 2014 PHB 玩家內容（12 職業、9 種族、PHB 法術／專長）。
- 介面與規則說明盡量繁中。專有名詞可在旁邊加小英文。
- GitHub Pages 靜態 PWA，加入主畫面後離線能看卡、改數字。
- 資料只存在這台手機；匯出／匯入 JSON 當備份。

**非目標（第一版不做）**

- 2024 規則、擴充書、兼職、裝備店、完整建角、骰子、帳號、雲端同步、DM／怪物／遭遇。
- 官方中文 PHB 全文（著作權）。法術／職業說明用 SRD 能用的內容，改寫成短中文。

之後若要 2024：另開資料檔，不改戰鬥頁結構。

## 形式

靜態 PWA（`manifest` + service worker），部署 GitHub Pages。  
無後端、無框架、無打包器。HTML／CSS／JS + JSON。

手機瀏覽器開一次 →「加入主畫面」。換手機靠匯出 JSON。

## 畫面

沒有底部導覽。一共四塊：

1. **戰鬥（首頁）**  
   名字、種族、職業等級。大顆 HP（點了加減，下限 0、上限最大 HP）。AC。攻擊／法術大按鈕（顯示命中與傷害／效果，不代骰）。法術位（點一下用掉，不能為負）。  
   右上「升級」。小選單：切換角色、新增角色、短休／長休、匯出／匯入。  
   狀態沒有時不佔位。技能、豁免、先攻／速度摺疊（先攻＝DEX 調整值，速度依種族）。

2. **升級**  
   從右上進入。一頁清單（這一級該勾的：HP、子職、ASI／專長、法術等）。全勾完才能套用。套用後回戰鬥頁，數字已改。

3. **建角**  
   第一次進來或「新增角色」。一頁：名字、種族、職業、等級（1–20）、六項屬性。送出後進戰鬥頁。

4. **摺疊抽屜**  
   技能／豁免、狀態（含死亡豁免）。不是獨立頁。

## 建角與升級規則（寫死，避免之後吵）

- 建角等級可 >1。HP：1 級用骰面最大值＋CON；之後每級用固定平均（骰面/2 無條件捨去 +1）＋CON。熟練與法術位依職業表自動算。
- 需要「選」的東西（子職、已知／準備法術、ASI／專長）不自動選。建完若還有沒選的，戰鬥頁頂部提示「還有未選項目」，點進去就是同一份清單。
- 準備 vs 已知：第一版不建模。角色只有一份「這張卡上的法術按鈕」。升級時「加入 N 個法術到這份清單」。
- AC、攻擊列：可編輯，不做背包模擬。建角給一個合理預設（例如法師 AC 10+DEX、法杖一筆攻擊），之後玩家自己改。
- 人類只用 PHB 標準（六項 +1）。不做變體人類。
- 建角不選背景。職業豁免熟練自動勾；技能熟練在摺疊列手動勾。
- 長休：法術位全滿，HP 拉回最大。短休：重置資料標成 `shortRest` 的次數（含術師法術位）。不做生命骰 UI。
- 不做兼職。

## 資料

靜態 JSON，跟網頁一起發布：

- `data/races.json` — PHB 9 種族
- `data/classes.json` — PHB 12 職業（每級：生命骰、獲得項目、法術位表、子職可選時機）
- `data/spells.json` — PHB 法術，短中文效果
- `data/feats.json` — PHB 專長，短中文

角色存在 `localStorage`，key 固定。結構：

```json
{
  "id": "…",
  "name": "艾琳",
  "race": "human",
  "class": "wizard",
  "level": 3,
  "abilities": { "str": 8, "dex": 14, "con": 13, "int": 16, "wis": 10, "cha": 12 },
  "hp": { "current": 14, "max": 20 },
  "ac": 12,
  "spellSlots": { "1": { "max": 4, "used": 1 }, "2": { "max": 2, "used": 0 } },
  "spells": ["mage-armor", "magic-missile", "fireball"],
  "attacks": [{ "name": "法杖", "bonus": 5, "damage": "1d6+2" }],
  "feats": [],
  "subclass": null,
  "pendingChoices": []
}
```

同一支手機可多張卡。切換只改「目前 id」。

## 資料流

- 規則 JSON 唯讀。離線時由 service worker 快取。
- 每次改 HP、法術位、套用升級：立刻寫 `localStorage`。
- 匯出：下載目前角色（或全部）JSON。匯入：驗證後加入或取代。
- 關掉再開：讀 `localStorage`。沒有角色 → 建角。

## 出錯

- 匯入不是 JSON、或缺名字／職業／屬性：不寫入，說明缺什麼。
- `localStorage` 寫失敗：提示先匯出；畫面上的數字先留著。
- 升級沒勾完：不能套用，標出還沒勾的。
- 第一次沒網路、快取還沒建：顯示「先連一次網」。
- 某職業某級資料缺失：該級清單顯示「這筆資料還沒做」，不套用半套。

不做雲端復原、不做多裝置合併。

## 技術結構（少檔案）

```
index.html
manifest.webmanifest
sw.js
css/app.css
js/app.js          // 畫面與點擊
js/store.js        // localStorage、匯出匯入
js/rules.js        // HP、熟練、法術位、升級清單
data/*.json
test/rules.test.js // node 跑 assert，不引入測試框架
```

GitHub Pages 發布根目錄。

## 怎麼驗

`node test/rules.test.js`：

- 法師 1 級建角：HP、熟練、1 環法術位。
- 法師 3→4：清單含 HP 與 ASI／專長；套用後 level=4、HP 用平均、法術位表正確。
- HP 不能低於 0、不能高於 max；法術位不能用成負的。
- 壞的匯入 JSON 被拒絕。
- 清單沒勾完不能套用。

真機人工：加入主畫面、斷網改 HP。

## 明確不做的簡化

- 法術準備／已知差一層：第一版合成一份按鈕清單。以後若要分準備欄，在角色物件加 `prepared[]`。
- AC／攻擊手填，不模擬盔甲與武器表。
- 沒有骰子。
