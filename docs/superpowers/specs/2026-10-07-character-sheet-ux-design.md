# 角色卡 UI／UX：戰鬥優先

## 方向
採用使用者選擇的 B 草圖：保留羊皮紙、酒紅與奇幻書冊風格，降低裝飾對閱讀與操作的干擾。沿用原生 HTML、CSS、JavaScript，不新增套件。

## 範圍與版面
- 角色名稱、出身與等級保留在頁首，角色卡／備忘錄／對照表使用清楚的分頁與目前頁面提示。
- 生命值是首要資訊：放大目前值與上限、提供生命比例條，保留直接輸入與增減按鈕。
- 護甲、先攻與速度集中排列；熟練、法術 DC 與法術攻擊仍可見，不刪除原有資訊。
- 短休、長休、專注操作移到生命區附近。沿用既有休息行為；實作前核對其確認與恢復效果，避免改變規則。
- 法術環顯示剩餘／總數，每個使用狀態同時具備視覺與輔助技術提示。
- 攻擊、資源與法術優先呈現；能力、豁免、技能、特性、專長、裝備與背包沿用可展開區塊，避免增加新的分頁層級。
- 桌機使用主內容與次要資訊雙欄，手機按戰鬥優先順序單欄排列，不依賴橫向捲動。

## 遊玩與編輯
沿用角色既有 locked 狀態，不新增模式資料或改變既有角色預設。將鎖定／解鎖改成清楚的「遊玩中／編輯資料」提示。遊玩時隱藏新增、刪除及角色設定操作，仍可調整生命、法術環、資源、狀態與其他既有允許操作。保留角色切換、升級、匯入、匯出與刪除確認。

## 建立角色與其他頁面
建立角色保留目前欄位與計算方式，整理欄位分組、必填提示、錯誤訊息及主要按鈕。共同字級、按鈕、焦點與間距改善套用到備忘錄及對照表，但不重做它們的功能或資訊架構。

## 實作界線
主要修改 css/app.css 與 js/app.js 的呈現及必要事件處理；需要時更新 index.html 與 sw.js 的靜態資產版本以避免舊快取。沿用 Rules 與 Store，不變更遊戲規則、資料格式或儲存鍵，也不搬移使用者資料。不做無關重構。

## 無障礙與回饋
主要觸控目標至少 44px，保留可見鍵盤焦點。輸入、圖示按鈕與可切換控制具有明確名稱和狀態，不只用顏色傳達。一般文字對比至少 4.5:1；支援減少動態效果。保留儲存失敗與刪除確認提示。

## 驗證
- 執行 node test/rules.test.js 與 node test/store.test.js。
- 為新增的非平凡呈現／互動邏輯留下最小可執行檢查。
- 檢查 375px 手機與 1280px 桌機排版、鍵盤焦點、編輯切換、生命增減、法術環、休息、建立角色與分頁。
- 檢查角色資料在重新整理後仍保留，匯入／匯出與原有操作未被版面改動破壞。
- 若無可用瀏覽器驗證工具，明確列出尚需人工驗證的項目，不宣稱已完成視覺驗證。
